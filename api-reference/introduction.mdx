The indexer exposes a small, read-focused HTTP API. The explorer uses it today, and you can use it from your own tools.

<Info>
  There's no public hosted instance yet. Run the indexer yourself with the [quickstart](/quickstart), then point the playground on each endpoint page at your server.
</Info>

## Base URLs

The API is split across the indexer's two processes.

| Process | Default address | Routes |
| --- | --- | --- |
| `live` | `HTTP_ADDR` or `METRICS_ADDR`, for example `http://localhost:9090` | `/v1/domains`, `/v1/verify`, `/healthz` |
| `serve` | `API_ADDR`, default `http://localhost:8080` | `/api/v1/analytics/*`, `/healthz` |

See [Configuration](/indexer/configuration) for how to expose each one.

## Authentication

None. Every endpoint is public and read-only, except `POST /v1/verify`, which accepts verification submissions.

## Rate limits

`POST /v1/verify` is limited to 10 requests per IP per minute. Over the limit it returns `429`. The window is fixed, so wait until the next minute before retrying. Read endpoints are not rate limited by the indexer, so put a proxy in front of a public deployment.

## Errors

Analytics and verification errors return JSON with an `error` field and a matching HTTP status:

```json
{ "error": "invalid parameter: limit 500 out of range [1, 100]" }
```

Domain endpoints never fail on input. A name or address that isn't known returns `200` with an empty result, and `indexed: false` means ingestion hasn't started yet.
