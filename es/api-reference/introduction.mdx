El indexer expone una API HTTP pequeña y orientada a la lectura. El explorer ya la usa, y también puedes usarla desde tus propias herramientas.

<Info>
  Todavía no hay una instancia pública alojada. Ejecuta el indexer por tu cuenta con la [guía de inicio rápido](/es/quickstart) y luego apunta el playground de cada página de endpoint a tu servidor.
</Info>

## URLs base

La API se reparte entre los dos procesos del indexer.

| Proceso | Dirección predeterminada | Rutas |
| --- | --- | --- |
| `live` | `HTTP_ADDR` o `METRICS_ADDR`, por ejemplo `http://localhost:9090` | `/v1/domains`, `/v1/verify`, `/healthz` |
| `serve` | `API_ADDR`, por defecto `http://localhost:8080` | `/api/v1/analytics/*`, `/healthz` |

Consulta [Configuración](/es/indexer/configuration) para ver cómo exponer cada uno.

## Autenticación

No hay. Todos los endpoints son públicos y de solo lectura, excepto `POST /v1/verify`, que recibe solicitudes de verificación.

## Límites de tasa

`POST /v1/verify` está limitado a 10 solicitudes por IP por minuto. Si superas el límite, devuelve `429`. La ventana es fija, así que espera al minuto siguiente antes de reintentar. El indexer no limita la tasa de los endpoints de lectura, así que coloca un proxy delante de cualquier despliegue público.

## Errores

Los errores de analítica y de verificación devuelven JSON con un campo `error` y el código de estado HTTP correspondiente:

```json
{ "error": "invalid parameter: limit 500 out of range [1, 100]" }
```

Los endpoints de dominios nunca fallan por la entrada. Un nombre o una dirección desconocidos devuelven `200` con un resultado vacío, e `indexed: false` significa que la ingesta todavía no ha comenzado.
